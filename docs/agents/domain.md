# 领域文档读取约定

本仓库采用单上下文布局（single-context）。以下约定规定工程技能如何读取领域词汇和架构决策，不要求先创建文档才能开始工作。

## 探索相关代码前

- 根目录 `GLOSSARY.md` 存在时，先读取领域术语及定义。
- 如果未来出现根目录 `GLOSSARY-MAP.md`，先读映射，再读与当前问题相关的各上下文 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与改动区域有关的架构决策。若未来改为多上下文布局，同时检查 `src/<上下文>/docs/adr/`。
- 上述文件或目录不存在时，直接继续工作，不把缺失当作错误，也不主动要求先补齐。只有术语或决策真正得到澄清时，再由 `/domain-modeling` 按需创建；它也可通过 `/grill-with-docs`、`/improve-codebase-architecture` 进入。

## 当前布局

以下是按需创建后的约定位置，不表示这些文件目前已经存在：

- `GLOSSARY.md`：整个项目共用的领域术语表。
- `docs/adr/`：架构决策记录。
- `baseline/`：当前第一方实现；`tests/`：回归测试。

没有多包工作区信号，不因存在 `third_party/` 上游源码快照而拆成多个领域上下文。

## 统一术语

Issue 标题、规格、研究假设、重构建议和测试名称涉及领域概念时，优先采用 `GLOSSARY.md` 中的词义，不随意改成近义词。确有缺失时，区分是自己引入了不必要的新概念，还是需要交给 `/domain-modeling` 澄清的真实缺口。

## 显式说明 ADR 冲突

若建议与现有 ADR 冲突，明确指出对应记录、冲突内容和重新讨论的理由，不静默推翻既有决策。
